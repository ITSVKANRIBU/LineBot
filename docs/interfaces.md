# 外部インターフェース仕様

このシステムが外部と接する境界を記述します。ここに書かれた契約は、LINE プラットフォーム、外部フォーム、外部サービスとの間で守られる必要があります。

## 全体像

```text
LINE プラットフォーム ──POST /callback──▶  Bot
外部フォーム          ──POST /specialvillage──▶  Bot
外部フォーム          ──GET  /callapi──▶  Bot

Bot ──▶ LINE Messaging API（返信）
Bot ──▶ Google Apps Script（役職画像の一覧）
Bot ──▶ GitHub Raw（既定の役職画像。上記の失敗時）
```

## 受信：LINE webhook

```text
POST /callback
```

LINE Messaging API からの webhook を受けます。`X-Line-Signature` ヘッダによる署名検証を通過したイベントだけが処理されます。

**処理するイベント**

| イベント | 動作 |
| --- | --- |
| テキストメッセージ | 内容に応じた村の作成・設定・参加（[game-spec.md](game-spec.md)） |
| ポストバック | ボタン押下に対応する処理（後述） |
| スタンプ | 製作者情報の返信 |

上記以外のイベント（友だち追加、画像、位置情報など）は受信しますが、何も返しません。

**ポストバックのデータ**

ボタンに埋め込まれる値は数値で、値域によって意味が変わります。

| 値 | 意味 |
| --- | --- |
| 0〜9 | お題候補の取得。この処理はユーザー ID を必要としない |
| 10〜9999 | 通常村の入室状況確認 |
| 10000 以上 | 特殊村の入室状況確認 |
| 数値以外 | 既定の応答 |

**制約**

LINE プラットフォームは、webhook に対して 2 秒以内の応答を要求します。現在の実装は返信 API の応答を同期的に待つため、この制約に対するマージンは実測で確認する必要があります（[architecture.md](architecture.md) の「既知の制約」参照）。

## 受信：村操作 API

```text
GET /callapi?message=<メッセージ>&userId=<ユーザー識別子>
```

LINE のトークへ送るのと同じ内容を `message` に渡すと、Bot が返すはずのメッセージを LINE Messaging API のメッセージ形式（JSON 配列）で返します。外部フォームから、LINE を経由せずに村を操作するための入口です。

**リクエスト**

| パラメータ | 必須 | 説明 |
| --- | --- | --- |
| `message` | ○ | 村番号、`お題` / `題` / `神` / `ランダム`、人数、またはお題の文字列 |
| `userId` | ○ | 参加者の識別子。呼び出し元が指定した値をそのまま使う |

**レスポンス**

| 状況 | 応答 |
| --- | --- |
| 正常 | HTTP 200。LINE メッセージ形式の JSON 配列 |
| `message` または `userId` が空 | HTTP 400（本文なし） |
| 対象の村が存在しない | HTTP 200。`村が作成されていません` のテキストメッセージ |
| 内部エラー | HTTP 500。`{"error":"内部エラーが発生しました。"}` |

CORS は有効です。ブラウザ上のフォームから直接呼び出せます。

**この API が持たない機能**

- **認証がありません。** `userId` は呼び出し元が自由に指定できます。他人の LINE ユーザー ID を知っていれば、その人として村を操作できます。
- **レート制限がありません。**
- **`@` で始まるコマンドを解釈しません。** `@取得` `@配布` `@特殊` `@逆村` `@わーわーず` を送ると、**お題の文字列として設定されます**。これらの機能を検証・利用する場合は LINE 経由で行う必要があります。
- **ポストバックとスタンプに対応しません。**

## 数値の解釈

数値をどう解釈するかは、LINE 経由と `/callapi` 経由で異なります。

| 入力値 | LINE 経由 | `/callapi` 経由 |
| --- | --- | --- |
| 10000 以上 | 特殊村へ参加 | 特殊村へ参加 |
| 1000〜9999 | 通常村へ参加 | 通常村へ参加 |
| 101〜999 | 村番号として扱う（該当なし） | 人数設定 |
| 100 以下 | 人数設定 | 人数設定 |

この差から、次の 2 つの帰結が生じます。

**LINE から設定できる参加人数は 100 人まで**です。101 以上は村番号として解釈されます。一方 `/callapi` からは 999 人まで設定できます。

**LINE から 101〜999 を送ると、必ず既定の応答が返ります。**村番号は 1000〜9999 の範囲で採番されるため、この範囲に該当する村は存在しません。

この不一致は意図的な統一の結果ではなく、経路ごとに境界値が決められた結果です。統一するには、どちらかの経路の既存の利用者に影響が出ます。現時点では既知の差分として記録し、変更していません。

## 受信：特殊村作成 API

```text
POST /specialvillage
Content-Type: application/json

{"message": ["1人目へのメッセージ", "2人目へのメッセージ", ...]}
```

配りたいメッセージの集合から特殊村を作成します。

**制約**

| 項目 | 上限 | 理由 |
| --- | --- | --- |
| メッセージ数 | 1〜100 件 | 通常村の参加人数上限（100 人）に揃える |
| 1 件の長さ | 5,000 文字 | LINE のテキストメッセージの上限 |

`null` と空文字は許容され、受け取った参加者には `メッセージは特にありません。` が返ります。

**レスポンス**

| 状況 | 応答 |
| --- | --- |
| 正常 | HTTP 200。`{"data":"<5 桁の村番号>"}` |
| JSON が不正、`message` が無い・空・101 件以上、5,000 文字超を含む | HTTP 400（本文なし） |
| 内部エラー | HTTP 500。`{"error":"内部エラーが発生しました。"}` |

`X-Content-Type-Options: nosniff` を付与します。CORS は有効です。

**検証を作成前に行う理由**

空の配列や長すぎるメッセージは、村を作った後では気付けません。空の村には誰も参加できず、長すぎるメッセージは LINE 側が送信を拒否します。どちらも番号を採番して利用者へ伝えた後に発覚すると、その村は使えないままレジストリを占有します。そのため**採番の前に弾きます**。

**この API が持たない機能**

認証とレート制限がありません。誰でも特殊村を作成できます。

## 送信：LINE Messaging API

利用者への返信は、webhook で受け取った reply token を使った返信 API で行います。プッシュ送信は使いません。

送信するメッセージ種別は、テキスト、画像、テンプレート（ボタン・確認）です。

**テンプレートの文字数制限への対応**

ボタンテンプレートの本文には文字数上限があり、お題を含むメッセージはこれを超えることがあります。お題の長さは利用者が決めるため、事前に制限できません。超えた場合は**テキストメッセージと入室状況の 2 通に分割して送ります**。メッセージが届かないより、見栄えを落とす方を選びます。

## 送信：役職画像の一覧（Google Apps Script）

役職に添える画像の一覧を、Google Apps Script のウェブアプリから取得します。

- 取得のタイミング: 起動直後と、以降 5 分間隔
- 応答の形式: `files` 配列。各要素が `name` と `url` を持つ
- `name` の規約: `<役職名>_<重み>_<任意の文字列>` の 3 部構成。この形式でない要素は無視される
- `<役職名>`: `INSIDER` / `VILLAGERS` / `GM` / `GOD`
- `<重み>`: 抽選での出現比率。値が大きいほど選ばれやすい

**取得に失敗した場合**、または該当する役職名の画像がない場合は、GitHub Raw に置かれた既定の画像を使います。画像の取得は配布の本質ではないため、失敗しても配布は続行します。

**URL の指定に関する注意**

Apps Script のデプロイ URL（`/macros/s/<デプロイ ID>/exec`）を指定します。ブラウザでこの URL を開くと別ドメインへリダイレクトされますが、**リダイレクト先の URL を設定してはいけません**。リダイレクト先に含まれるキーは一時的な発行物で、失効すると以降エラーを返し続けます。

**この外部化の意図**

画像を差し替えるたびに再デプロイするのを避けるためです。役職画像は見た目の要素であり、アプリケーションのリリースサイクルに縛る理由がありません。

## 内包：お題辞書

お題は 8,436 語の CSV としてアプリケーションに同梱され、**起動時に一度だけ読み込まれます**。各行の 1 列目がお題です。

難易度は行番号の範囲として表現されるため、**行を追加・削除・並べ替えると難易度の境界がずれます**。辞書を更新する場合は、難易度の境界値も併せて見直す必要があります。

読み込みに失敗した場合、お題の自動取得は何も返しません。ランダム村はお題が空のまま作成されます。
