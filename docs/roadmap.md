# 今後の計画

このページは、**まだ実施していない**事柄を記録します。ここに書かれた内容はいずれも現状のシステムには反映されていません。現状は [overview.md](overview.md) 以下の各文書を参照してください。

## Oracle Cloud Always Free への移行（検討中）

**ステータス: 検討中。着手していない。実施するかどうかも決定していない。**

### 概要

現在 LineBot は Heroku の Eco プラン（**$5/月 = $60/年**）で、スリープさせずに稼働しています。

**この $5/月をなくすため**、**LineBot を Oracle Cloud Always Free の ARM VM へ移す**構成を検討しています。移行後は自前の VM 上で、リバースプロキシによる TLS 終端と、systemd によるプロセス管理を行う構成になります。費用は自己所有ドメインの維持費（$10.44/年）だけになり、**$0 にはなりません**。

設計の詳細は [2026-08-22 LineBot を Oracle Cloud Always Free へ移行する設計](superpowers/specs/2026-08-22-linebot-oracle-cloud-migration-design.md) にあります。このページでは重複して記述しません。

### 検討中である理由

**着手の条件が、こちらで制御できない外部要因に依存しているためです。**

Always Free の ARM インスタンスは在庫が逼迫しており、確保できない状態が続くことがあります。加えて、リージョンの選択はアカウント作成時に確定し、**後から変更できません**。確保できるかどうかが分かるのは、この不可逆な選択を済ませた後です。

さらに、**無料枠そのものが予告なく縮小され得ます**。2026 年 6 月に ARM 枠が 4 OCPU / 24 GB から 2 OCPU / 12 GB へ半減し、告知はドキュメントの更新だけで、8 月から超過インスタンスが停止・終了されました。移行先の枠は「契約」ではありません。

そのため、この設計は次の方針を取っています。

- **着手の条件**: 対象リージョンでインスタンスが起動していること
- **条件を満たさない間**: Heroku のまま運用を続け、Heroku 側に一切手を触れない
- **一定期間試して確保できない場合**: この設計は「保留」で終わらせる

**動いている製品を、成立するか分からない構成と引き換えにしません。**

### 決まっていること・決まっていないこと

**設計上の判断は済んでいます。**構成、プロセス管理、TLS、デプロイ手順、切替前の検証項目、ロールバック手順は設計書に記述済みです。

**未確定なのは、実行しなければ決まらないパラメータだけです。**ドメイン名、VM の公開 IP、SSH 鍵ペアが該当します。

### この移行が扱わないこと

- ゲーム状態の永続化（[architecture.md](architecture.md) の設計判断のまま）
- アプリケーションコードのリファクタリング
- 公開 API への認証の追加

移行はホスティング先の変更であり、**このシステムの外部仕様とアーキテクチャは変わりません**。移行が完了しても [game-spec.md](game-spec.md) と [architecture.md](architecture.md) の内容は変わらず、[operations.md](operations.md) だけが書き換わります。

### 移行の前後で変わること

| 項目 | 現在 | 移行後（案） |
| --- | --- | --- |
| 稼働環境 | Heroku | Oracle Cloud の ARM VM |
| webhook URL | Heroku のホスト名 | 自己所有ドメインのサブドメイン |
| 秘密情報の保管 | Heroku の環境変数 | VM 上のファイル |
| プロセス管理 | Heroku の dyno | systemd |
| TLS | Heroku が終端 | VM 上のリバースプロキシが終端 |
| デプロイ | Heroku の GitHub 連携 | CI から VM へ配置し、ヘルスチェックで検証 |
| 費用 | $5/月（$60/年） | ドメイン維持費のみ（$10.44/年） |
| Heroku 固有ファイル | `Procfile` / `app.json` / `system.properties` | 解約後に撤去 |

## 課題として認識しているが、計画していないもの

[architecture.md](architecture.md) の「既知の制約」に挙げた次の項目は、問題として認識していますが、**着手の計画はありません**。いずれも現在の Heroku 上でも同じように存在しており、上記の移行が作り出すものでも、解消するものでもありません。

| 項目 | 解消に必要なこと |
| --- | --- |
| 公開 API が無認証 | 認証の導入。外部フォーム側の改修を伴うプロダクト判断 |
| 単一プロセス前提 | 状態の外部化。永続化を持たないという設計判断の見直し |

上記の移行を実施する場合、リバースプロキシで閉じられる範囲（レート制限とリクエストサイズの上限）は、その作業に含める想定です。
